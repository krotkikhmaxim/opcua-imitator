# Техническое задание на разработку системы сохранения/загрузки состояния OPC UA сигналов

## 1. Общие сведения

### 1.1 Назначение системы
Разработка полноценной системы сохранения и загрузки состояния OPC UA сигналов в формате JSON для веб-приложения мониторинга и управления подъёмной машиной ПМ.

### 1.2 Основание для разработки
Данный функционал является расширением существующего веб-приложения для мониторинга OPC UA сервера и реализует возможность:
- Сохранения текущих значений всех сигналов в файл
- Загрузки сохранённого состояния обратно в OPC UA сервер
- Экспорта/импорта конфигураций для различных режимов работы

## 2. Требования к функциональности

### 2.1 Backend (серверная часть)

#### 2.1.1 Структура хранения данных
| Параметр | Описание |
|----------|----------|
| **Директория хранения** | `saved_states/` (создаётся автоматически) |
| **Формат файлов** | JSON (кодировка UTF-8) |
| **Структура JSON** | `{name, description, created, version, signal_count, signals}` |
| **Именование файлов** | `{name}_{timestamp}.json` (timestamp: YYYYMMDD_HHMMSS) |

#### 2.1.2 API эндпоинты

| Метод | Эндпоинт | Назначение | Входные данные | Выходные данные |
|-------|----------|------------|----------------|-----------------|
| GET | `/api/states/list` | Получение списка сохранённых состояний | - | Массив объектов с информацией о состояниях |
| POST | `/api/states/save` | Сохранение текущего состояния | `{name, description}` | `{status, filename, message}` |
| POST | `/api/states/load` | Загрузка состояния в OPC UA | `{filename}` | `{status, loaded_count, errors, message}` |
| DELETE | `/api/states/delete/{filename}` | Удаление сохранённого состояния | `filename` (в URL) | `{status, message}` |
| POST | `/api/states/export` | Экспорт состояния как скачиваемый файл | `{name, description}` | JSON файл (FileResponse) |
| POST | `/api/states/import` | Импорт состояния из загруженного файла | `file` (multipart/form-data) | `{status, filename, signal_count, message}` |

#### 2.1.3 Обработка сигналов при сохранении
- **Обязательное условие**: Сохраняются ТОЛЬКО сигналы с непустыми значениями в кэше
- **Типизация значений**: 
  - `bool` → сохраняется как `boolean`
  - `int`/`float` → сохраняется как число
  - Прочие типы → преобразуются в строку

#### 2.1.4 Обработка сигналов при загрузке
| Условие | Действие |
|---------|----------|
| Сигнал найден в конфигурации | Запись значения в OPC UA |
| Сигнал не найден в конфигурации | Пропуск, добавление в список ошибок |
| Сигнал только для чтения (`writable: false`) | Пропуск, добавление в список ошибок |
| Ошибка записи в OPC UA | Добавление в список ошибок |
| Успешная запись | Обновление кэша, инкремент счётчика |

#### 2.1.5 WebSocket уведомления
После успешной загрузки состояния отправляется WebSocket сообщение:
```json
{
  "type": "state_loaded",
  "loaded_count": number,
  "errors": string[]
}
```

### 2.2 Frontend (клиентская часть)

#### 2.2.1 Компонент StateManager

| Элемент | Назначение |
|---------|------------|
| **Кнопка "Сохранить состояние"** | Открытие модального окна для сохранения |
| **Кнопка "Импорт"** | Открытие диалога выбора JSON файла |
| **Кнопка "Обновить"** | Обновление списка состояний |
| **Список состояний** | Отображение всех сохранённых состояний с карточками |
| **Модальное окно** | Форма для ввода названия и описания состояния |

#### 2.2.2 Функции StateManager

| Функция | Описание |
|---------|----------|
| `loadStates()` | Загрузка списка сохранённых состояний с сервера (каждые 10 секунд) |
| `handleSaveState()` | Отправка запроса на сохранение состояния |
| `handleLoadState(filename)` | Отправка запроса на загрузку состояния с подтверждением |
| `handleDeleteState(filename)` | Удаление состояния с подтверждением |
| `handleExportState(filename)` | Скачивание JSON файла состояния |
| `handleImportState(event)` | Загрузка и импорт JSON файла |

#### 2.2.3 Отображение карточки состояния

| Поле | Источник данных |
|------|-----------------|
| Название | `state.name` или `filename` |
| Количество сигналов | `state.signal_count` |
| Описание | `state.description` |
| Дата создания | `state.created` (формат: DD.MM.YYYY HH:MM) |
| Размер файла | `state.size` (в B/KB/MB) |

#### 2.2.4 Визуальные состояния

| Состояние | Отображение |
|-----------|-------------|
| Успешная операция | Зелёное сообщение (background: #dcfce7) |
| Ошибка | Красное сообщение (background: #fee2e2) |
| Информация | Синее сообщение (background: #dbeafe) |
| Загрузка | Кнопки disabled, анимация |
| Пустой список | Отображение "Нет сохранённых состояний" |

#### 2.2.5 Требования к модальному окну

| Элемент | Требование |
|---------|------------|
| **Поле "Название"** | Обязательное поле, валидация на пустую строку |
| **Поле "Описание"** | Необязательное, многострочный ввод (textarea) |
| **Информация о сигналах** | Отображение количества сигналов в таблице |
| **Кнопка "Отмена"** | Закрытие модального окна без сохранения |
| **Кнопка "Сохранить"** | Активна только при заполненном названии |
| **Закрытие по клику вне окна** | Поддержка клика по overlay |

### 2.3 Интеграция с App.tsx

| Требование | Описание |

## 4. Структура данных

### 4.1 Формат JSON файла
```json
{
  "name": "string - Название состояния (обязательное)",
  "description": "string - Описание состояния (опционально)",
  "created": "string - ISO 8601 дата создания",
  "version": "string - Версия формата (1.0)",
  "signal_count": "number - Количество сохранённых сигналов",
  "signals": {
    "signal_id_1": "boolean | number | string - Значение сигнала",
    "signal_id_2": "boolean | number | string - Значение сигнала"
  }
}
```

### 4.2 Список состояний (API ответ)
```json
[
  {
    "filename": "string - Имя файла",
    "name": "string - Название состояния",
    "description": "string - Описание",
    "created": "string - Дата создания",
    "size": "number - Размер в байтах",
    "signal_count": "number - Количество сигналов"
  }
]
```

### 4.3 Ответ на загрузку состояния
```json
{
  "status": "ok",
  "loaded_count": "number - Успешно загружено сигналов",
  "errors": "string[] - Список ошибок",
  "message": "string - Сообщение о результате"
}
```

## 6. Требования к обработке ошибок

### 6.1 Ошибки серверной части

| Код HTTP | Ситуация | Обработка |
|----------|----------|-----------|
| 404 | Файл не найден при загрузке/удалении | Возврат сообщения с описанием |
| 400 | Неверный формат JSON при импорте | Возврат сообщения о неверном формате |
| 500 | Ошибка чтения/записи файла | Возврат сообщения с деталями |
| 500 | Ошибка подключения к OPC UA | Возврат сообщения об ошибке |

### 6.2 Ошибки клиентской части

| Ситуация | Обработка |
|----------|-----------|
| Пустое название состояния | Отображение ошибки "Введите название состояния" |
| Ошибка сети | Отображение ошибки с возможностью повтора |
| Загрузка с ошибками | Отображение частичного успеха с списком ошибок |
| Попытка загрузки невалидного файла | Отображение ошибки "Неверный JSON формат" |
