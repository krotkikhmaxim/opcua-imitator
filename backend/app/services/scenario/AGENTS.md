# Сценарии аварий

Модель подъёмной машины (`hoist.py`), шкала изменений (`timeline.py`) и
движок проигрывания (`engine.py`). Правила, которые легко нарушить правкой:

- **Последствия сценария задаёт человек, а не ПЛК.** Имитатор программу не
  исполняет: отпадание реле ТП, выбег привода, действия машиниста прописаны
  в эпизоде. Новый или изменённый эпизод сверяется с цепочкой защиты в
  программе ПЛК проекта. Сценарий, противоречащий программе, учит станцию
  находить причину, которой в объекте нет.
- **Код ПЛК сюда не копируется.** В репозитории уже лежат теги проекта;
  имена блоков, защёлок и выражения программы не добавляются ни в код, ни в
  комментарии, ни в эталонные ответы.
- **Исправное состояние — данные с оговорками.** `BASELINE` покрывает каждый
  опубликованный сигнал (это держит тест). Значение, чья полярность из
  программы не следует однозначно, обязано стоять в `ASSUMPTIONS`.
- **Журнал правды не публикуется в OPC UA.** Только HTTP API и JSONL:
  станция не должна «находить» причину в самом эталоне.
- **SourceTimestamp — момент сценария, а не момент записи.** Отставание
  записи видно в `max_lag_ms`, но в метки времени не попадает.
- **Режим `real` запрещён.** Запись ушла бы во внешний сервер, то есть в ПЛК.
- **Модель детерминирована по seed.** Случайность только через переданный
  `random.Random`, время — только миллисекунды шкалы; шкала запрещает писать
  сигнал задним числом.
